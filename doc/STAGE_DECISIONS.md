# 단계별 결정 & 세부 기획 체크리스트

각 단계를 **시작하기 전에** 이 문서의 해당 단계 섹션을 열어, 결정 항목을 정하고 세부 기획 표를 채운 뒤 코딩을 시작합니다.

---

## 📖 사용법

1. 단계를 시작하면 해당 섹션의 **🔀 결정 항목** 표에서 `결정` 칸을 채웁니다.
   - 고민이 길어지면 `기본안`을 그대로 택해도 됩니다. 기본안은 [STEP_BY_STEP_GUIDE.md](STEP_BY_STEP_GUIDE.md)의 예시 코드가 따르는 값입니다.
   - 결정한 내용이 기본안과 다르면, 예시 코드를 그대로 쓰지 말고 결정에 맞게 바꿔서 구현합니다.
2. **📝 세부 기획** 표(수치, 문구, 목록)를 채웁니다. 채운 값이 곧 구현 명세가 됩니다.
3. **⏭️ 미리 생각해 둘 것**은 지금 정하지 않아도 되지만, 현재 단계 구현이 나중에 발목을 잡지 않도록 염두에 둘 항목입니다.
4. 확정된 게임 규칙은 [GAME_DESIGN.md](GAME_DESIGN.md)에도 반영합니다. (이 문서 = 결정 과정 기록, GAME_DESIGN = 확정된 규칙)
5. 결정 항목은 `D<단계>-<번호>` (예: `D4-3`)로 부르며, 커밋 메시지나 코드 주석에서 참조할 수 있습니다.

## 1단계: 입출력 & 기본 루프

### 🔀 결정 항목

| ID | 결정할 것 | 선택지 | 기본안 | 결정 |
| :---: | :--- | :--- | :--- | :--- |
| D1-1 | 게임 제목 | 자유 | "Rust Text RPG" | Rust Hero |
| D1-2 | 메뉴 번호 표기 방식 | `[1] 던전 입장` / `1. 던전 입장` | ⚠️ 현재 문서에 두 가지가 섞여 있음 → 하나로 통일 | `[1] 던전 입장` (`[번호]` 형식) |
| D1-3 | 문체 | 존댓말("~했습니다") / 반말·게임체("~했다!") | 시스템 메시지는 존댓말, 조우 연출은 게임체 (현재 예시 혼용) | 게임체 ("~했다!") |
| D1-4 | 이름 입력 규칙 | 빈 이름 허용 여부, 최대 글자 수, 공백 허용 | 빈 이름은 재입력, 길이 제한 없음 | 빈 이름 불가(재입력), 1~10자 제한(`chars().count()`), 공백 허용 |
| D1-5 | 화면 지우기 | 매 메뉴마다 화면 지우기 / 계속 아래로 출력 | 지우지 않음 (구현 단순, 로그 확인 쉬움) | 지우지 않음 (로그 보존, 추후 변경 가능) |

### 📝 세부 기획
- **타이틀 화면 문구**:
  ```text
  ==================================================
                    ★ RUST HERO ★
           - 끝없는 심연과 영웅의 연대기 -
  ==================================================

    던전 최심부에 도사린 악을 처단할 용사를 기다린다!

    [1] 새로운 모험 시작
    [2] 게임 종료

  ==================================================
  ```
- **공통 UI 규칙**:
  | 요소 | 형식 |
  | :--- | :--- |
  | 입력 프롬프트 | `선택 > ` |
  | 이름 입력 프롬프트 | `용사의 이름을 입력해라 (1~10자) > ` |
  | 잘못된 입력 안내 | `잘못된 입력이다. 다시 선택해라!` |
  | 이름 길이 오류 안내 | `이름은 1자 이상 10자 이하여야 한다!` |
  | 기본 구분선 | `==================================================` |

### ⏭️ 미리 생각해 둘 것
- 8단계에서 타이틀 메뉴에 `[이어하기]`가 들어갑니다. 타이틀 메뉴를 `새 게임 / 종료` 구조로 만들어 두면 나중에 항목만 추가하면 됩니다.
- 이름 길이 제한을 둔다면 한글은 `name.len()`(바이트 수)이 아니라 `name.chars().count()`(글자 수)로 세야 합니다.
